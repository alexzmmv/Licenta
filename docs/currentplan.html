Task 1.1: Fix Silent Salt Failure in PBKDF2 SECURITY
B5
  • GJournal/Sources/Repository/AuthManager.swift:291-293

SecRandomCopyBytes return value is discarded. If it fails, the salt is all-zeros → predictable PBKDF2 hash.

Step 1: Add a test in AuthManagerSecurityTests.swift that verifies registration with a valid PIN produces a non-zero salt in the Keychain.
Step 2: Fix generateRandomSalt() to check the return status:
private func generateRandomSalt() throws -> String {
    var bytes = [UInt8](repeating: 0, count: Self.saltLength)
    let status = SecRandomCopyBytes(kSecRandomDefault, Self.saltLength, &bytes)
    guard status == errSecSuccess else {
        throw AuthError.keychainError
    }
    return Data(bytes).base64EncodedString()
}
Step 3: Update storePBKDF2(pin:) to propagate the throw from generateRandomSalt().
Step 4: Update all callers of storePBKDF2 to handle the new throwing signature.

Phase 3 — Security Hardening High

4 tasks~60 min
Task 3.1: Fix Time-Based Lockout Bypass SECURITY
H2
  • GJournal/Sources/Repository/AuthManager.swift:195-202, 301-303

PIN lockout uses wall-clock time. Attacker can advance system clock to bypass.

Step 1: Add a test in AuthManagerSecurityTests that verifies lockout persists even when the system clock appears to jump forward (mock the timestamp source).
Step 2: Replace Date().timeIntervalSince1970 with a monotonic counter. Use ProcessInfo.processInfo.systemUptime or store a server-independent counter. Since Keychain survives reboots but uptime resets, the safest approach is to store the fail count and require a minimum time per app session:
// Store the session-start uptime and use relative deltas
private let sessionStart = ProcessInfo.processInfo.systemUptime

func lockoutRemaining() -> TimeInterval {
    let failCount = readIntFromKeychain(key: failCountKey)
    guard failCount >= Self.maxAttempts else { return 0 }
    // Use session-relative timing — reboot clears the timer (acceptable tradeoff)
    let lockoutStart = lastLockoutSessionUptime
    let elapsed = ProcessInfo.processInfo.systemUptime - lockoutStart
    return max(0, Self.lockoutDuration - elapsed)
}

Task 4.6: Fix DBSCAN Core Point Off-by-One
H8b
  • GJournal/Sources/Services/Clustering/DBSCANClusterer.swift:67

Standard DBSCAN includes the query point in its ε-neighborhood. Current impl excludes it, making minPoints effectively minPoints + 1.

Step 1: Include the query point index in regionQuery results, OR adjust the minPoints threshold by -1 at the call site. The cleanest fix is to include self:
func regionQuery(_ pointIndex: Int, eps: Double) -> [Int] {
    var neighbors = [pointIndex]  // include self
    for j in 0..<distanceMatrix.count where j != pointIndex {
        if distanceMatrix[pointIndex][j] <= eps {
            neighbors.append(j)
        }
    }
    return neighbors
}
Step 2: Verify with existing tests — note this may change clustering results. Update test expectations if needed.
Step 3: Build + test → commit.
⚠️ Careful: This changes clustering behavior. The current parameters were likely tuned around the off-by-one. You may need to adjust minPoints defaults or verify clusters still look correct with real data.
