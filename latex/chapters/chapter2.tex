\chapter{System Requirements and Specification}
\label{ch:requirements}
\section{Scope and Objectives}
The application targets iOS and performs all natural language processing locally on the device. It provides a privacy-first micro‑journaling experience with short text entries, generates semantic embeddings and emotion labels for each entry on device, groups entries into semantically coherent clusters presented via list, calendar, and graph views, preserves user privacy by avoiding cloud storage or remote inference, and maintains acceptable interactive performance on devices from iPhone 14 and newer.

\section{Assumptions and Constraints}
The following assumptions and constraints are used throughout the specification:
\begin{itemize}
  \item Target platform: iOS 26+.
  \item All NLP inference and clustering run on device; cloud sync is not supported.
  \item Entry length is limited to approximately 500--600 characters.
  \item Minimum supported device class: iPhone 14 or equivalent NPU capability.
  \item Development stack: Swift + SwiftUI, Core ML for inference, SwiftData for local persistence, Python (RTX2070) for model fine‑tuning and conversion.
  \item Models will be quantized and converted to Core ML format to reduce size and improve inference speed.
  \item Where user input is incomplete, reasonable defaults are chosen and documented in this chapter.
\end{itemize}

\section{Functional Requirements}

\subsection{Core Functionality}
\begin{description}
  \item[FR1] \textbf{Create micro‑journal entry.} The user can create a short text entry. The entry editor opens a focused input screen that "takes the story" from the user.
  \item[FR2] \textbf{Entry views.} The user can view entries in a calendar view, a chronological list view, and a graph view that visualizes clusters and relationships.
  \item[FR3] \textbf{On‑device analysis.} Immediately after saving an entry, the system generates a semantic embedding and runs an emotion classifier locally.
  \item[FR4] \textbf{Clustering.} The system groups entries into clusters using an on‑device clustering algorithm. Clustering runs incrementally on new entries and can be re‑computed in batch.
  \item[FR5] \textbf{Search and filtering.} The user can search entries by text and filter by date, detected emotion, and cluster membership.
\end{description}

\subsection{Editing and Deletion Policies}
\begin{description}
  \item[FR6] \textbf{Edit policy.} The user may edit entries created on the same calendar day. Edits update embeddings and cluster assignments.
  \item[FR7] \textbf{Deletion policy.} The user may delete entries. Deleted entries are soft‑deleted and retained for a configurable grace period (default three days) before permanent removal.
\end{description}

\section{Non‑Functional Requirements}
\begin{description}
  \item[NFR1] \textbf{Privacy.} No user text or embeddings leave the device. No cloud services are used for inference or storage.
  \item[NFR2] \textbf{Performance.} Interactive analysis latency should be under five seconds on the minimum target device for a single entry; background batch clustering may take longer.
  \item[NFR3] \textbf{Model footprint.} Individual on‑device models should be quantized and kept as small as practical; a soft target is under 100 MB combined for core models.
  \item[NFR4] \textbf{Battery and resource usage.} Background processing must be scheduled to minimize battery impact; heavy tasks should run when the device is idle or charging.
  \item[NFR5] \textbf{Accessibility.} The UI must follow platform accessibility guidelines (dynamic type, VoiceOver support).
\end{description}

\section{System Architecture}

\subsection{Components}
The UI Layer (SwiftUI) covers the entry editor, calendar, list, graph, and settings screens. The Persistence Layer (SwiftData) is a local database for entries, embeddings, cluster metadata, and user settings. The Inference Engine (Core ML) loads and runs on‑device models for embedding generation and emotion classification. The Clustering Engine implements a density‑aware algorithm (DBSCAN or similar) optimized for small datasets and incremental updates. A Scheduler and Background Worker manages periodic batch clustering, model updates, and low‑priority maintenance tasks.

\section{Data Flow and Processing Pipeline}
The canonical data flow for a new entry is:

\begin{enumerate}
  \item User creates an entry in the editor and saves it.
  \item The Persistence Layer stores the raw text and metadata.
  \item The Inference Engine generates a semantic embedding and an emotion label for the entry.
  \item The embedding and label are stored alongside the entry.
  \item The Clustering Engine performs an incremental update to cluster assignments.
  \item The UI updates calendar, list, and graph views to reflect the new entry and cluster membership.
\end{enumerate}

A periodic batch job re‑computes clusters and cluster summaries during idle time or when the device is charging.

\section{Use Cases and User Flows}

\subsection{Use Case UC1: Create Entry}
The user opens the entry editor, types a short entry (up to 400 characters total, 150 per field), and taps Save. The system stores the entry, runs on‑device inference, updates cluster assignments, and refreshes the calendar, list, and graph views so the new entry appears with its detected emotion and cluster.

\subsection{Use Case UC2: View Insights}
From the Insights or Graph view, the user sees clusters, representative entries, and an emotion distribution. Tapping a cluster reveals its member entries.

\subsection{Use Case UC3: Edit Entry}
Editing is permitted only for entries created on the same calendar day. When the user edits an entry, the system re‑computes the embedding and updates the cluster membership accordingly.

\subsection{Use Case UC4: Delete Entry}
A deleted entry is soft‑deleted and retained for a configurable grace period (default three days) before permanent removal.

\section{Model Selection and Formats}
Three embedding strategies are implemented behind a common \texttt{EmbeddingService} protocol. all-MiniLM-L6-v2 produces 384-dimensional mean-pooled embeddings and is packaged as a 43\,MB Core ML bundle; it is the default. nomic-embed-text-v1.5 is trained with Matryoshka Representation Learning and produces embeddings at \{64, 128, 256, 512, 768\} dimensions by truncating its output; the default truncation is 256 dimensions and the Core ML package is 261\,MB. Apple NLEmbedding ships with the operating system (zero bundle cost) and produces 512-dimensional vectors. The emotion classifier is MobileBERT fine-tuned for three epochs on GoEmotions, with 28 original labels collapsed to 12 classes (Joy, Sadness, Anger, Fear, Love, Surprise, Disgust, Anxiety, Excitement, Gratitude, Hope, Guilt), packaged as a 94\,MB Core ML bundle. All models are converted using coremltools on a Python workstation.

\section{Clustering Strategy}
The system uses DBSCAN with adaptive parameters. Epsilon is calibrated per corpus as the 10th percentile of pairwise cosine distances; \texttt{minPoints} scales with corpus size between a minimum of 3 and a maximum of 11. For MRL-truncated embeddings, epsilon is further scaled by $\sqrt{d/768}$ to compensate for the compressed distance range at lower dimensions. Cluster names are derived by extracting frequent nouns and adjectives from member entries, with a fallback to the dominant emotion label. A background batch job re-runs clustering when the device is idle.

\section{Privacy}
By design, the app does not transmit journal text, embeddings, or cluster metadata off device. No cloud services are involved in any part of the pipeline.

\section{Performance Targets and Testing}
Interactive inference (embedding + emotion classification) should complete within 5 seconds on iPhone 14; incremental cluster membership updates should complete within 2 seconds per new entry. Batch re‑clustering is acceptable to run for several minutes during idle or charging periods. Combined model size should stay under 100 MB where possible, and the journal database should remain responsive up to 200 MB of stored entries. Testing covers latency, memory, and battery impact on representative devices (iPhone 14 Plus, iPhone 15), and clustering quality via silhouette and ARI metrics on synthetic and anonymized sample data.

\section{Acceptance Criteria}
The prototype is acceptable when FR1--FR7 are implemented and demonstrable, on‑device inference meets the performance targets on the minimum device, data remains local with no off-device transmission, and clustering produces coherent groups visible in the graph view.

\section{Implementation Plan and Milestones}
\begin{enumerate}
  \item Project scaffolding: SwiftUI screens for editor, calendar, list, graph, and settings; SwiftData schema for \texttt{Bit} and \texttt{Cluster} entities.
  \item AI pipeline: Core ML integration for all-MiniLM-L6-v2 embedding, nomic-embed-text-v1.5 MRL embedding, Apple NLEmbedding, and MobileBERT emotion classifier; protocol-based \texttt{EmbeddingService} and \texttt{EmotionService} abstractions.
  \item Clustering engine: adaptive DBSCAN, incremental update on entry save, background batch re-clustering, cluster naming.
  \item Graph visualization: force-directed layout, hub-and-spoke rendering, pan/zoom interaction.
  \item Evaluation: Python benchmarks on STS-B and TwentyNewsgroups; domain validation on 100 labelled journal entries.
\end{enumerate}
